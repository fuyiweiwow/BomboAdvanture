# 参数化像素五官组件实验设计

日期：2026-07-26

## 1. 目标

在已经提取的男女基础脸上，使用本地、可复现的像素规则生成可组合的眉毛、眼睛和耳朵组件。首轮实验生成：

- 细眉
- 小眼
- 精灵耳

组件必须能根据提示词或结构化因子生成，而不是只能复制一张固定的眉毛或眼睛。后续同一协议应支持斗鸡眼、兽耳、哭眉、猫眼、胡子、发型等扩展，并可被其他像素游戏复用。

本轮不调用 Image API，不依赖云端模型。基础脸和已有素材只作为像素风格、位置和颜色参考。

## 2. 已确认的基础素材

- 男性基础脸：`assets/test/face_bases_v1/male/`，来源 `face10101`
- 女性基础脸：`assets/test/face_bases_v1/female/`，来源 `Face10701`
- 女性默认基础层保留原始腮红，同时提供独立 `blush` 层
- 每个基础脸包含 28 帧：四向站立帧和四向行走帧
- 原始五官标注：`assets/test/male_face_v2/annotations.json`

基础脸的五官位置是透明孔。透明孔不代表错误，它为运行时组件覆盖预留空间。生成组件必须覆盖所需孔位，避免缩小眼睛后露出背景。

## 3. 总体架构

运行时和离线工具都遵循以下层次：

```text
FaceBase
  + SocketCover
  + Eye
  + Brow
  + Ear
  + Blush
  + Hair
  + Beard
  + Mouth
  = Composite
```

`FaceBase` 只包含皮肤、轮廓和默认保留的腮红。五官组件不写回基础脸。`Composite` 只用于预览和验收，正式资源仍按组件加载。

每个组件生成器接收统一的上下文：基础脸角色、方向、帧号、锚点、解析后的因子和 seed。组件输出使用原始帧坐标，不通过缩放整个角色来对齐。

## 4. 因子与提示词协议

输出清单必须保存原始提示词和解析后的因子，结构如下：

```json
{
  "base_id": "female",
  "prompt": "细眉、小眼、精灵耳",
  "seed": 20260726,
  "factors": {
    "brow": {"style": "thin", "thickness": 1, "curve": 0},
    "eye": {"size": "small", "scale_x": 0.75, "scale_y": 0.8, "iris": "blue", "pupil_offset": [0, 0]},
    "ear": {"type": "elf", "length": 4, "tip_raise": 3, "outer_spread": 2}
  }
}
```

提示词解析只做确定性的别名映射，不尝试理解任意自然语言。首轮至少支持：

| 提示词 | 因子 |
|---|---|
| `细眉`、`细的眉毛` | `brow.style=thin` |
| `小眼`、`小眼睛` | `eye.size=small` |
| `精灵耳`、`尖耳` | `ear.type=elf` |
| `兽耳` | `ear.type=beast`，为后续扩展保留接口 |
| `斗鸡眼` | `eye.pupil_offset`，本轮暂不生成 |

未识别的词应进入 `warnings`，不能静默改变结果。显式因子优先于默认值，seed 只影响允许随机化的细节，不改变组件类别。

## 5. 首轮组件规则

### 5.1 细眉

- 以原始眉毛标注区域的左右锚点为基准。
- 厚度固定为 1 像素。
- 保留左右独立的弧度、倾斜和间距参数。
- 颜色从基础脸眉毛参考色阶中选择，支持后续换色。

### 5.2 小眼

- 眼睛可见区域缩放到原眼区约 70% 到 80%。
- 眼白、虹膜、瞳孔和高光同步缩放，不能只缩小瞳孔。
- 眼睛中心和左右间距仍由方向锚点控制。
- 首轮使用现有像素色阶，不生成抗锯齿半透明像素。

### 5.3 精灵耳

- 以原耳朵区域的内侧连接点作为锚点。
- 耳尖向外上方延长 3 到 4 像素。
- 外轮廓、内耳阴影和肤色高光分别绘制。
- 不修改基础脸轮廓；精灵耳可以超出原耳朵范围。
- `ear.type=beast` 使用同一接口，后续可增加圆耳、猫耳、狼耳等形状。

### 5.4 SocketCover

由于基础脸在原五官位置透明，小眼和细眉如果只绘制自身像素会留下孔洞。`SocketCover` 是独立的皮肤色覆盖层：

- 只覆盖原始五官孔位，不覆盖脸部外轮廓。
- 颜色由基础脸孔位边缘的已有皮肤色阶决定。
- 不使用邻域无限扩散，不改变脸部轮廓，不调用图像模型。
- 可单独输出和检查，后续可以改为更精确的手工 patch。

## 6. 输出结构

首轮输出放在 `assets/test/face_factor_v1/`，不覆盖 `face_bases_v1`：

```text
assets/test/face_factor_v1/
  male/
    socket_cover/
    eye/
    brow/
    ear/
    composite/
    preview/
  female/
    socket_cover/
    eye/
    brow/
    ear/
    composite/
    preview/
  prompts/
    factors.json
  manifest.json
```

每个角色先输出四向站立帧，再输出完整 28 帧。每个 PNG 保持来源帧的原始尺寸和坐标原点。`manifest.json` 记录来源基础脸、提示词、因子、seed、文件路径、警告、每帧尺寸和透明孔覆盖统计。

## 7. 数据流

```text
prompt text
  -> deterministic parser
  -> normalized factors + warnings
  -> per-direction anchor context
  -> socket cover + component rasterizers
  -> component PNGs + JSON metadata
  -> composite preview
  -> pixel and visual QC
```

失败时必须停止当前 variant 并报告原因，包括：缺失基础帧、方向锚点不存在、因子值越界、组件覆盖不足、输出尺寸变化。不能用隐式默认值掩盖错误。

## 8. 验收标准

1. 男、女基础脸均能生成首轮三因子组合。
2. 四向站立预览中没有黑色背景孔或未覆盖的透明缺口。
3. 组件之间没有非预期覆盖：耳朵不遮眼睛，眉毛不进入虹膜区。
4. 小眼的眼白、虹膜、瞳孔和高光随尺寸同步变化。
5. 精灵耳在左右方向保持内侧连接正确，耳尖朝向外上方。
6. 每个输出可由 `prompt + factors + seed` 重复生成相同像素结果。
7. 原始基础脸目录不被修改。
8. 至少有自动化测试覆盖提示词解析、参数边界、输出尺寸、透明孔覆盖和 seed 可复现性。

## 9. 后续本地模型接入边界

本地模型可以在离线阶段提出新眉毛、眼睛、耳朵形状，但模型输出必须经过像素化、锚点归一化和组件协议转换后才能进入资源库。游戏运行时不依赖模型推理。这样既能保留提示词扩展能力，也能保证动画帧、碰撞边界和多角色复用的稳定性。
