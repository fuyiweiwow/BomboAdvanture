# 美术系统去风险路线

## 目标

参考代码只用于开发期理解接口、验证方向和检查运行时契约。最终发布资源不得依赖 `original/`、旧 QQT 帧数据、旧像素掩码、旧调色板或未确认授权的音频/字体。

本项目保留高层设计目标：大头小身、清晰的像素五官、独立组件换装和四方向动画。高层比例与视觉目标不等于复制原作具体像素；所有发布资产必须重新设计、重新绘制并记录来源。

## 阶段计划

### 阶段 0：来源台账与隔离

- 将 `original/`、旧脸部图集、旧标注和旧测试输出标记为 `reference_only`。
- 区分 `assets/test/` 实验资源与正式运行资源。
- 建立资产来源记录：来源类型、生成器版本、seed、参数、许可证和 SHA-256。
- 修复工具对固定 `E:\WorkProject\...` 路径的依赖，使测试可在当前工程目录运行。

### 阶段 1：自有脸部与人物基底

- 保留现有组件化运行时契约：`Base + SocketCover + Eye + Brow + Ear + ...`。
- 重新绘制自有头部轮廓、皮肤色板、五官插槽和方向锚点。
- 可以保留“大头比例”和“大眼视觉语言”等高层目标，但不得读取或复制旧脸部像素、旧 mask、旧坐标标注和旧 palette。
- 先生成四方向站立帧，再生成完整 28 帧。
- 保留已验证的眼睛/眉毛参数模型和方向处理经验，但在新基底上重新渲染。
- 通过尺寸、透明孔覆盖、图层重叠、seed 可复现和源文件独立性测试。

### 阶段 2：耳朵随机生成

- 耳朵始终作为独立图层，不回写脸部基底。
- 支持 `size`、`angle`、`point`、`inner_color`、`visibility` 等因子。
- 当前 `native_face_v2` 已先实现人耳，再扩展精灵耳、兽耳等类型。
- 同一 seed 必须产生完全一致的 PNG 和 manifest。
- 接入人物预览和运行时组件加载。

### 阶段 3：完整人物生成

- 身体、服装、发型、帽子和其他装饰层。
- 统一四方向、动画帧、锚点、调色板、组件 JSON 和预览格式。
- 正式资源只使用本地规则生成、团队原创或有明确商业授权的素材。

### 阶段 4：怪物与 NPC

- 建立自有怪物轮廓、颜色、动作和掉落展示资源。
- 复用人物资产契约，但不复用 QQT 角色图形或名称。
- 记录每个怪物的生成参数和来源。

### 阶段 5：地图与场景

- 替换地板、墙体、障碍物、箱子、环境装饰和编辑器图标。
- 地图数据可以保留游戏逻辑结构，但正式贴图必须来自自有绘制或明确授权来源。

### 阶段 6：音乐、音效和字体

- 最后替换音乐、音效和字体。
- 每个文件必须有许可证、购买凭证或原创声明。
- 未确认授权的 `ogg`、`ttc`、`ttf` 不进入发布包。

### 阶段 7：发布前清理

- 移除或迁出 `original/` 和所有仅供参考的资源。
- 扫描运行时路径，确认没有旧资源读取。
- 扫描文件 SHA、品牌名称、角色名称、字体、音频和许可证记录。
- 使用干净资源目录重新导出并验证 Godot 包。

## 当前工作顺序

1. 自有脸部基底和眼睛/眉毛重新渲染。
2. 自有耳朵随机生成。
3. 完整人物生成。
4. 怪物生成。
5. 地图生成。
6. 音乐、音效和字体。
7. 移除参考代码和发布前扫描。
