## 阶段收束备忘（供后续讨论）

本阶段先冻结“首个可验证闭环”，后续开发按以下顺序推进，避免在素材和 UI 尚未稳定时扩大玩法面：

1. **优先补齐掉落配置工具链**：为 `assets/adventure/rogue_drop_pool.json` 增加编辑器校验/预览，检查道具 ID 存在、概率范围、权重总和和稀有度；配置错误应在启动或 CI 中明确失败。
2. **再定义重复强化规则**：决定炸弹上限、威力、速度的软上限/硬上限，以及重复拾取是否递减；先写纯规则测试，再接 UI 显示。
3. **之后做构筑内容**：协同、套装、互斥和词缀需要稳定的道具标签与数值规则，暂不与当前最小掉落池混实现。
4. **最后接入长局与元进度**：炼药产物、解锁、商店刷新和长局模拟应建立在可持久化数据契约之上，并继续使用固定种子静默回归。

当前明确暂缓：补齐旧素材、重做完整战斗 UI、一次性加入大量道具、以及在没有平衡测试前开放武器/药水商店持久化。缺失资源继续使用 Godot 原生控件或无视觉占位。

本阶段验收证据：`run-silent-tests.ps1` 全量 9/9 通过；`-Module rogue_drop_integration` 通过；源码工作树无非 `.import` 修改，未跟踪 `.import/.gd.uid` 为 0。
